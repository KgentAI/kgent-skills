# 0014 — decision-navigator 逐轮评审门（事实接地 + 逻辑审查）

decision-navigator 在每次向用户呈报之前（澄清问题批、每轮收敛汇报、准则提议、终局简报前，至多 6 次/运行）触发一次评审门：新起一个独立评审（子代理派发；宿主无派发能力则由 skill 以同一清单内联复查并标注），只读地审一份评审包（请求与用户逐字答复、问题状态账本、证据清单、受审工件），出具固定两节的评审结论——事实接地（新增引用必须可解析、抽样 ≤3 条实证复核）与逻辑审查。评审者与导航者分离（maker/checker）：评审者永不实施修正、永不面向用户；可修缺陷由 decision-navigator 修正（致命/可修修正后恰一次 delta 再查），未决缺陷折入既有简报章节（假设与待确认 前缀「评审未决」、高风险注记、轮首一行注记），承载前提被致命否决时走既有排序挂起降级。此门常开：中间产物（澄清问题、准则提议）与终局产物同样塑造决策，只审终局会让被污染的前提在第 1–3 轮就获得用户背书。

## Considered Options

- **仅终局审查一次**：被否——有缺陷的假设与引用在中间轮就被用户确认，终局才发现为时已晚；且澄清问题本身（诱导性问题、假二选一）无人复核。
- **单一评审会话贯穿全程**：被否——跨轮积累语境使评审者被自身既往结论锚定，且依赖宿主会话续接能力，可移植性差。
- **评审者直接修正**：被否——破坏 maker/checker 分离（loop-verifier 约定：评审者永不修）；修正权与否决权同手会掩盖分歧。
- **简报新增固定章节承载评审结论**：被否——触发 `dn_brief_check` 硬合同连锁改动（checker + 测试矩阵 + property tests），而折入既有章节读者收益相同。

## Consequences

- SKILL.md 重编号：方案评审为 §6，决策简报延为 §7；内部交叉引用随之更新。
- 每次运行至多 6 次评审派发——常开门的成本被显式接受（评审包是小工件，评审远轻于导航主流程）。
- 评审者只读（B12 全程只读不变）：引用解析与实证复核只经 integration skill 读车道 / 宿主检索。
- 评审永不静默跳过：派发失败重试一次后申报「评审未执行」再继续；内联复查必须标注。
- 验证分期：本阶段 evals 走内联路径（`run-agent-evals.py` 无 Task 工具，恰为其验证面），评审结论文法由 `tools/dn_review_check.py` 机器可检；真派发 eval 支持（runner allowlist 扩展）延后为独立后续。
- 结构 evals 可断言：评审门标记逐轮在场、执行方式标注、`评审未决` 折入、致命→排序挂起、实证复核计数 ≤3。
