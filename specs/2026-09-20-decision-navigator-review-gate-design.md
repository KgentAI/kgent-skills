## 决策

decision-navigator 增设**评审门**：在每次向用户呈报之前，由一个新起的**独立评审**对一份**评审包**出具两节式**评审结论**（事实接地 + 逻辑审查），导航者据此修正后再呈报。关键裁决：

1. **触发面（逐轮常开）**：§1 澄清问题批前、每 §3 收敛轮的进展报告+追加澄清前、§4 准则提议前、§5+§6 终局一次（简报前）。不设 §0/§2 门（无用户面呈报）；不提供关闭开关——「跳过检查当它最要紧」恰是错误失败态。
2. **终局评审范围**：仅审 §5/§6 工件；此前各轮已各有其门，未决项经问题状态账本（待确认）向终局传递。不整链重审。
3. **评审包（固定四件，取自既有流程产物，不新增格式）**：① 请求原文与用户逐字答复；② 问题状态账本（编号 + 状态 用户已给/引用来源/假设/待确认 + 依: + 引用）；③ 证据清单（本轮检索所得：标题 + 原生 URL + 关键论断）；④ 受审工件（本轮将呈报用户的完整内容）。
4. **评审结论（固定两节）**：事实接地——新增引用逐条标注「已解析/不可解析」，抽样 ≤3 条实质论断实证复核（评审者重读源文）；逻辑审查——无效推理、无支撑推断、方案间矛盾、隐藏前提，受审工件为问题时尤查诱导性提问与假二选一。每条发现标注 **严重级**（致命/可修/轻微）与 **核对方式**（实证复核/一致性核对）。
5. **maker/checker 分离**：评审者永不实施修正、永不直接面向用户、无写操作（B12 不变）；修正由 decision-navigator 完成。
6. **修正与再评审**：致命/可修——导航者修正后对该 gate **恰一次 delta 再查**（仅查修正处）；轻微——修正后不再查。每 gate 再查上限 1 次，无修正循环。
7. **致命降级复用**：承载前提被致命否决 → 走既有零证据降级路径（排序挂起 + 说破），不新造机制。
8. **未决浮出（折入，不改简报文法）**：未修缺陷在 假设与待确认 以 `评审未决` 前缀列出；重大缺陷同时在 高风险注记 提示；中间轮轮首一行注记「评审：已修正 a 处；未决 b 处」。
9. **派发或内联（不静默跳过）**：宿主具备子代理派发能力（Claude Code Task 等）→ 派发，执行方式标注 `派发评审`；否则导航者以同一清单内联复查，标注 `内联复查`；派发失败重试一次，仍败 → 申报 `评审未执行` 后继续（诚实纪律，同检索缺失申报）。
10. **引用复核只读**：解析与实证复核只经 integration skill 读车道 / 宿主检索；评审者工具面为只读。
11. **语言跟随请求**：评审结论与注记语言 = 请求语言（既有不变量延伸至评审面）。
12. **验证分期**：结构/单元现在做（`dn_review_check.py` + evals 内联路径断言）；run-agent-evals.py 的 Task 工具扩展延后（非目标），真派发路径先以人工 transcript 审查覆盖一次。

## 操作流

```
§0  Ensure kgent Is Set Up                       （不变）
§1  请您澄清一下这些细节（batched clarification）——【评审门 → 呈报】
§2  问题拆解：先理清要回答哪些子问题               （不变，无门）
§3  信息收集与问题细化（≤3 轮；ADR 0013）
      每轮 6 拍……进展报告 + 问题图 + 追加澄清 ——【评审门 → 呈报】
§4  评价标准提议（propose-then-confirm）——————【评审门 → 呈报】
§5  方案生成与排序                                （不变）
§6  方案评审（事实接地 + 逻辑审查）★新增——————【终局评审门：审 §5+§6 一次】
      修正 → （致命/可修）恰一次 delta 再查 → 折入
§7  决策简报（唯一交付物）★由 §6 顺延             未决缺陷折入既有章节
```

SKILL.md 内部交叉引用（「§6 简报」等）随重编号同步更新；numbering 承重，逐处核对。

## 评审包 / 独立评审清单 / 评审结论（文法草案）

**评审包**（导航者组装，随 gate 附给评审者）：

```
【评审包】
1. 请求与答复      请求原文 + 用户逐字答复（至本轮）
2. 问题状态账本    编号 | 状态(用户已给/引用来源/假设/待确认) | 依:Qn | 引用
3. 证据清单        本轮检索所得：标题 + 原生 URL + 关键论断
4. 受审工件        本轮将呈报用户的完整内容
```

**独立评审清单**（派发 prompt 与内联复查同一份，SKILL.md 内联承载）：

1. 只读：仅读评审包与引用解析所需源文（integration skill 读车道 / 宿主检索）；禁止一切写。
2. 事实接地：新增引用逐条标注 已解析/不可解析；抽样 ≤3 条实质论断重读源文实证复核；其余仅一致性核对并如实标注核对方式。
3. 逻辑审查：无效推理、无支撑推断、方案间矛盾、隐藏前提；受审工件为问题时尤查诱导性提问、假二选一。
4. 分级：致命（承载前提被否 / 引用虚构）；可修（表述过强、缺引用、可弱化）；轻微（措辞、格式）。
5. 输出：仅评审结论（下述文法）；不改工件、不答复用户。
6. 语言跟随请求。

**评审结论**（机器可检——与 `tools/dn_review_check.py` 逐字对齐，exit 0 = 合规）：

```
【评审门 · 执行方式：派发评审|内联复查|评审未执行】
## 事实接地
- 已解析引用 n/n（不可解析逐条列为发现）
- [致命|可修|轻微][实证复核|一致性核对] <定位> — <缺陷> → <建议（不实施）>
（无缺陷：未发现事实接地缺陷。已解析引用 n/n；实证复核 m/≤3。）
## 逻辑审查
- [致命|可修|轻微] <定位> — <推理缺陷>
（无缺陷：未发现逻辑缺陷。）
```

`评审未执行` 时两节以单行申报替代（原因 + 影响），仍算合规形态（诚实申报优先于假装通过）。

### 失败模型

| # | 模式 | 捕获层 |
|---|---|---|
| FM-R1 | 评审未发生却报「已评审」（表演性评审） | 结构 evals：每个用户面呈报前须有 `【评审门 · 执行方式：…】` 标记且执行方式 ∈ 枚举；transcript 人工审查抽查 |
| FM-R2 | 评审者自身幻觉（复核断言与源文不符） | 实证复核须由评审者亲自重读源文 + 结论内注明核对方式；致命/可修 delta 再查；transcript 人工审查 |
| FM-R3 | 修正引入新缺陷 | 致命/可修修正后恰一次 delta 再查（上限 1）；轻微不触发（显式接受） |
| FM-R4 | 评审包遗漏不利证据（导航者博弈） | 评审包为固定四件、取自既有流程产物，无可裁剪面；人工审查抽查包完整性 |
| FM-R5 | 修正循环不收敛 | 每 gate delta 再查上限 1 次（机器可断言：同一 gate 至多两个评审结论） |
| FM-R6 | 派发失败被静默跳过 | 重试 1 次 → `评审未执行` 申报形态（dn_review_check 合规形态之一）；禁止无标记跳过 |
| FM-R7 | 评审者越权写 | 清单第 1 条禁写 + 只读工具面；B12 不变量与既有 eval 守卫不变 |
| FM-R8 | 实证复核失控烧时 | 上限机器可检：结论内实证复核计数 ≤3；引用解析不设样（可解析性检查为轻量操作） |
| FM-R9 | 有派发能力却走内联省事 | 本阶段靠 transcript 人工审查（runner 无 Task 工具，evals 天然全走内联；真派发断言随 runner 扩展后续补） |
| FM-R10 | 评审面语言漂移 | 语言跟随请求不变量延伸；英文 eval 案例断言 |

## 风险与开放问题

- **延迟成本**：至多 6 次派发/运行。已显式接受（ADR 0014）；若实战过重，后续可议「轻量 gate」（免实证复核的一致性核对档），不在本 spec。
